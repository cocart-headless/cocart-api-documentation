# Introduction

[Astro](https://astro.build) is a modern web framework that ships zero JavaScript by default, loading it only where you need interactivity. Its island architecture makes it a strong fit for headless storefronts — static product pages with dynamic cart and account components exactly where needed.

This guide walks you through setting up an Astro project configured to work with the CoCart API.

## Why Astro for headless commerce?

- **Island architecture** — static product pages with interactive cart and checkout components only where needed
- **Server Islands** — render dynamic components (cart count, user pricing) server-side on otherwise cached pages
- **Framework agnostic** — use React, Vue, Svelte, or Solid for interactive islands
- **Fast by default** — ships zero JS unless a component needs it
- **SEO friendly** — static generation with per-route server rendering when needed

## Prerequisites

- **Node.js 18.17.1** or higher (Astro 6 requires **Node.js 22.12.0+**)
- A WordPress site with WooCommerce and CoCart installed
- Basic knowledge of JavaScript/TypeScript

## Create a new Astro project

```bash
npm create astro@latest my-headless-store
```

When prompted:

- **How would you like to start?** → Empty
- **Install dependencies?** → Yes
- **Initialize git repository?** → Yes
- **TypeScript?** → Yes (recommended)

```bash
cd my-headless-store
```

## Install Tailwind CSS v4

Tailwind v4 integrates directly with Astro's Vite pipeline — no separate Astro integration needed.

```bash
npx astro add tailwind
```

This installs `tailwindcss` and `@tailwindcss/vite`, and updates your Astro config automatically.

Create a global CSS file at `src/styles/global.css`:

```css
@import "tailwindcss";
```

Import it in your layout (we'll create this in a moment):

```astro
---
// src/layouts/Layout.astro
---
<html>
  <head>
    <link rel="stylesheet" href="/src/styles/global.css" />
  </head>
  <!-- ... -->
</html>
```

<Note>
  Tailwind v4 uses CSS-based configuration instead of a `tailwind.config.mjs` file. Customize your theme directly in `global.css` using `@theme`.
</Note>

## Environment variables

Astro supports type-safe environment variables through the `astro:env` module. Define your schema in `astro.config.mjs`:

```javascript
import { defineConfig, envField } from 'astro/config';
import tailwindcss from '@tailwindcss/vite';

export default defineConfig({
  vite: {
    plugins: [tailwindcss()],
  },
  env: {
    schema: {
      PUBLIC_STORE_URL: envField.string({
        context: 'client',
        access: 'public',
        default: 'https://yourstore.com',
      }),
    },
  },
});
```

Create a `.env` file:

```bash
PUBLIC_STORE_URL=https://yourstore.com
PUBLIC_COCART_ENCRYPTION_KEY=your-secret-encryption-key
```

<Note>
  Variables prefixed with `PUBLIC_` are exposed to client-side code. Never put secrets in public variables.
</Note>

Then import with full type safety:

```typescript
import { PUBLIC_STORE_URL } from 'astro:env/client';
```

Or use the standard `import.meta.env.PUBLIC_STORE_URL` if you prefer the simpler approach.

## Install the CoCart SDK

```bash
npm install @cocartheadless/sdk
```

The SDK includes a dedicated [Astro adapter](/sdk/typescript/frameworks/astro) that handles cart session persistence between server-side rendering and client-side code — no cookies needed.

## Create the CoCart API client

Create `src/lib/cocart.ts` using the SDK's Astro adapter:

```typescript
// src/lib/cocart.ts — browser client (used in <script> tags and client-side components)
import { createBrowserClient, attachCartKeyHeader } from '@cocartheadless/sdk/astro';

const client = createBrowserClient(import.meta.env.PUBLIC_STORE_URL, {
  encryptionKey: import.meta.env.PUBLIC_COCART_ENCRYPTION_KEY,
});

await client.restoreSession();
attachCartKeyHeader(client);

export { client };
```

For server-side usage (Astro pages and API routes), import the server client directly where needed:

```typescript
// In any .astro page or API route
import { createServerClient } from '@cocartheadless/sdk/astro';

const client = createServerClient(import.meta.env.PUBLIC_STORE_URL, Astro.request);
```

<Tip>
  The Astro adapter uses encrypted `localStorage` and an `X-Cart-Key` header to share cart state between browser and server — no cookies required. See the [Astro adapter guide](/sdk/typescript/frameworks/astro) for full details.
</Tip>

## Server Islands for dynamic components

Server Islands let you embed server-rendered components inside otherwise static pages. This is ideal for e-commerce — your product pages stay cached and fast while the cart counter, user greeting, or personalized pricing renders fresh on every request.

First, enable server-side rendering for on-demand components. In `astro.config.mjs`:

```javascript
import { defineConfig, envField } from 'astro/config';
import tailwindcss from '@tailwindcss/vite';
import node from '@astrojs/node';

export default defineConfig({
  output: 'static',
  adapter: node({ mode: 'standalone' }),
  vite: {
    plugins: [tailwindcss()],
  },
  env: {
    schema: {
      PUBLIC_STORE_URL: envField.string({
        context: 'client',
        access: 'public',
        default: 'https://yourstore.com',
      }),
    },
  },
});
```

Install the Node adapter:

```bash
npx astro add node
```

Create a server island component at `src/components/CartCount.astro`:

```astro
---
import { createServerClient } from '@cocartheadless/sdk/astro';

const client = createServerClient(import.meta.env.PUBLIC_STORE_URL, Astro.request);
const cart = await client.cart().get();
const count = cart.getItemCount();
---

<a href="/cart" class="relative inline-flex items-center">
  Cart
  {count > 0 && (
    <span class="ml-1 inline-flex items-center justify-center rounded-full bg-indigo-600 px-2 py-0.5 text-xs text-white">
      {count}
    </span>
  )}
</a>
```

Use it on any static page with `server:defer`:

```astro
---
import Layout from '../layouts/Layout.astro';
import CartCount from '../components/CartCount.astro';
---

<Layout title="My Store">
  <nav class="flex items-center justify-between p-4">
    <a href="/" class="text-xl font-bold">My Store</a>
    <CartCount server:defer>
      <span slot="fallback">Cart</span>
    </CartCount>
  </nav>
  <!-- rest of the static page -->
</Layout>
```

The page is statically cached, but the cart count renders server-side on every request. The `fallback` slot shows while the island loads.

## Create API endpoints

Astro supports server-side API routes for proxying cart operations. Create `src/pages/api/cart/add.ts`:

```typescript
import type { APIRoute } from 'astro';
import { createServerClient } from '@cocartheadless/sdk/astro';

export const POST: APIRoute = async ({ request }) => {
  const client = createServerClient(import.meta.env.PUBLIC_STORE_URL, request);

  try {
    const { productId, quantity = 1 } = await request.json();
    const response = await client.cart().addItem(productId, { quantity });

    return new Response(response.toJson(), {
      status: 200,
      headers: { 'Content-Type': 'application/json' },
    });
  } catch (error) {
    return new Response(JSON.stringify({ error: (error as Error).message }), {
      status: 500,
      headers: { 'Content-Type': 'application/json' },
    });
  }
};
```

## Test your setup

Create a test page at `src/pages/index.astro`:

```astro
---
import Layout from '../layouts/Layout.astro';
import { createServerClient } from '@cocartheadless/sdk/astro';

const client = createServerClient(import.meta.env.PUBLIC_STORE_URL, Astro.request);
const products = await client.products().list({ per_page: 6 });
---

<Layout title="My Headless Store">
  <main class="container mx-auto px-4 py-12">
    <h1 class="text-3xl font-bold mb-8">Products</h1>

    <div class="grid grid-cols-1 gap-6 sm:grid-cols-2 lg:grid-cols-3">
      {products.map((product: any) => (
        <div class="border rounded-lg p-4">
          <h2 class="font-semibold text-lg">{product.name}</h2>
          <p class="text-zinc-600 dark:text-zinc-400 mt-1">
            {product.prices.currency_symbol}{product.prices.price}
          </p>
        </div>
      ))}
    </div>
  </main>
</Layout>
```

npm run dev

## Troubleshooting

### CORS errors

If you see CORS errors when calling CoCart from the browser, see the [CORS documentation](/cors) for configuration options.

### API connection issues

1. Verify `PUBLIC_STORE_URL` in your `.env` is correct
2. Ensure CoCart is installed and activated
3. Test the endpoint directly: `https://yourstore.com/wp-json/cocart/v2/products`
4. Check the [Error Codes reference](/api-reference/v2/error-codes) for specific error responses
