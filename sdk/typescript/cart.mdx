The Cart API handles all shopping cart operations — adding items, updating quantities, applying coupons, managing shipping, and more.

**How cart sessions work:**

- **Guest customers** — The first request creates a new guest session. The server returns a `Cart-Key` which the SDK extracts and stores automatically. All subsequent requests use this key.
- **Authenticated customers** — The server identifies the cart by the WordPress user account. No cart key is needed.

```ts
const cart = client.cart();
```

## Create Cart

Create a new guest cart session without adding items. Only available for non-authenticated (guest) users.

<Note>Requires CoCart Starter.</Note>

```ts
const response = await cart.create();
console.log(response.get('cart_key')); // 'guest_abc123...'
```

## Get Cart

```ts
const response = await cart.get();

// With parameters
const response = await cart.get({
  _fields: 'items,totals', // Limit returned fields
  thumb: 'true',           // Include product thumbnails
  default: 'true',         // Return default cart data
});
```

### Type-Safe Field Filtering

`getFiltered()` tells the server to send back only the fields you list. Less data transferred and TypeScript compile-time safety for the returned type. It's still one normal cart request — this just adds `?_fields=items,totals` to the URL so the server trims its reply:

```ts
const response = await cart.getFiltered(['items', 'totals']);
const data = response.toObject();

data.items;    // CartItem[]  ✓
data.totals;   // CartTotals  ✓
data.currency; // TS compile error — not requested  ✓
```

## Client-Side Validation

The SDK validates inputs before sending anything to the server. Invalid product IDs or quantities throw immediately without a network request:

```ts
import { ValidationError } from '@cocartheadless/sdk';

try {
  await cart.addItem(-1, 0);
} catch (e) {
  if (e instanceof ValidationError) {
    // e.message => "Product ID must be a positive integer"
    // No network request was made
  }
}
```

Validation rules:

- **Product ID** — Must be a positive whole number, or a SKU like `'BLUE-SHIRT-L'` (`addItem`, `addVariation`, and the main product in `addItems`). A SKU gets checked by the store, not the SDK — the SDK only blocks input it already knows is wrong (empty, negative, zero, or not a whole number).
- **Quantity** — Must be a positive number (`addItem`, `addVariation`). `updateItem()` also accepts `0`, which the server treats as removing the item.

<Note>
  This doesn't apply to the individual products inside an `addItems()` group — those must be numeric IDs, not SKUs.
</Note>

You can also use the validation functions directly:

```ts
import { validateProductId, validateQuantity, validateEmail } from '@cocartheadless/sdk';

validateProductId(123);           // OK
validateProductId('BLUE-SHIRT-L'); // OK — treated as a SKU, resolved server-side
validateProductId(-1);            // throws ValidationError
validateQuantity(2);              // OK
validateQuantity(0);              // throws ValidationError
validateEmail('user@example.com'); // OK
validateEmail('not-an-email');     // throws ValidationError
```

## Adding Items

<Note>
  Product ID and quantity are converted to text before being sent (e.g. `2` becomes `"2"`) — that's just how the SDK talks to the server, nothing you need to do yourself.
</Note>

### Add a Simple Product

```ts
// Product ID 123, quantity 2
const response = await cart.addItem(123, 2);

// Shorthand
const response = await cart.add(123, 2);

// A SKU also works — the server resolves it to a product ID
const response2 = await cart.addItem('BLUE-SHIRT-L', 1);
```

### Add with Options

```ts
const response = await cart.addItem(123, 1, {
  item_data: {
    gift_message: 'Happy Birthday!',
    engraving: 'John',
  },
  email: 'customer@email.com',
  return_item: true,  // Return only the added item details
});
```

### Add a Variable Product

```ts
const response = await cart.addVariation(456, 1, {
  attribute_pa_color: 'blue',
  attribute_pa_size: 'large',
});

// Or using addItem with variation option
const response = await cart.addItem(456, 1, {
  variation: {
    attribute_pa_color: 'blue',
    attribute_pa_size: 'large',
  },
});
```

### Add Multiple Children of a Grouped Product

`addItems()` is specifically for adding multiple children of a WooCommerce **Grouped Product** to the cart in one request — not a generic "add several unrelated products" call. Pass the grouped product's own ID (a number or a SKU, same as `addItem()`), plus a map (or array) of its child product IDs to quantities. The child IDs must be numeric — they don't accept a SKU:

```ts
// Shorthand: child product id => quantity
const response = await cart.addItems(100, {
  '101': 2,
  '102': 1,
});

// Full array form
const response = await cart.addItems(100, [
  { id: 101, quantity: 2 },
  { id: 102, quantity: 1 },
]);
```

For adding several _unrelated_ products in one request, use [`client.batch()`](/sdk/typescript/extensions#batch-requests) instead — one `add-item` sub-request per product.

## Updating Items

Every item in the cart has a unique **item key** — a long string like `abc123def456...` that identifies that specific item. You receive item keys in cart responses and use them to update or remove items.

```ts
const response = await cart.updateItem('abc123def456...', 5);

// With additional options
const response = await cart.updateItem('abc123def456...', 3, {
  item_data: { gift_wrap: true },
});
```

### Update Multiple Items at Once

<Note>
  This issues one `item/{key}` request per entry, sequentially — not a single bulk round trip — and resolves with the response from the last request only. For a true single-request bulk update, see [Batch Requests](/sdk/typescript/extensions#batch-requests).
</Note>

```ts
// Shorthand: item_key => quantity
const response = await cart.updateItems({
  'abc123def456...': 3,
  'def789ghi012...': 1,
});

// Full format with additional options
const response = await cart.updateItems([
  { item_key: 'abc123def456...', quantity: 3 },
  { item_key: 'def789ghi012...', quantity: 1 },
]);
```

</Note>

### Get Item Count

<Note>

Those cost the same as a full `cart.get()`.
</Note>

```ts
const response = await cart.getItemCount();
```

## Customer Details

### Update Customer

<Note>
  `billing` and `shipping` both use the same plain, unprefixed field names (`first_name`, `address_1`, ...) — the SDK adds the `s_` prefix (`s_first_name`, `s_address_1`, ...) that the server expects for shipping fields internally, so you never need to write it yourself.

  `shipping` is optional. If you omit it, `billing` is mirrored into the shipping fields automatically — the same as leaving "Ship to a different address" unchecked at a normal WooCommerce checkout — so the destination country's required-field validation still passes. Pass `shipping` explicitly (with its own full address) to ship somewhere different than billing; this also sets `ship_to_different_address`.
</Note>

```ts
// Update billing address — shipping mirrors billing automatically
const response = await cart.updateCustomer({
  first_name: 'John',
  last_name: 'Doe',
  email: 'john@example.com',
  phone: '+1234567890',
  address_1: '123 Main St',
  city: 'New York',
  state: 'NY',
  postcode: '10001',
  country: 'US',
});

// Ship to a different address than billing
const response = await cart.updateCustomer(
  {
    first_name: 'John',
    last_name: 'Doe',
    email: 'john@example.com',
    phone: '+1234567890',
    address_1: '123 Main St',
    city: 'New York',
    state: 'NY',
    postcode: '10001',
    country: 'US',
  },
  {
    first_name: 'John',
    last_name: 'Doe',
    address_1: '456 Oak Ave',
    city: 'Los Angeles',
    state: 'CA',
    postcode: '90001',
    country: 'US',
  },
);
```

## Batch Requests

<Note>Requires the CoCart Plus plugin.</Note>

For a true single-request bulk operation — as opposed to `updateItems()`/`removeItems()`, which issue one sequential request per item (see above) — dispatch multiple sub-requests in one call via `client.batch()`. This can mix any operations, including adding items:

```ts
const response = await client.batch([
  { method: 'POST', path: '/cocart/v2/cart/add-item', body: { id: '123', quantity: '2' } },
  { method: 'POST', path: '/cocart/v2/cart/item/abc123def456...', body: { quantity: '3' } },
  { method: 'DELETE', path: '/cocart/v2/cart/item/def789ghi012...' },
]);
```

The server returns one merged, up-to-date cart response (if all sub-requests succeed) along with notices for each operation, instead of one response per request.

<Note>
  `addItems()` (see [Add Multiple Children of a Grouped Product](#add-multiple-children-of-a-grouped-product)) only handles adding children of one WooCommerce Grouped Product — it's not a general "add several unrelated products" call. For adding multiple unrelated products in a single request, use `client.batch()` with one `add-item` sub-request per product, as shown above.
</Note>

`Cart.batchUpdateItems()` and `Cart.batchRemoveItems()` are typed convenience wrappers over `client.batch()` for the common case of bulk item updates/removals, accepting the same shorthand/full formats as `updateItems()`/`removeItems()`:

```ts
// Update multiple items in one request
const response = await cart.batchUpdateItems({
  'abc123def456...': 3,
  'def789ghi012...': 1,
});

// Remove multiple items in one request
const response = await cart.batchRemoveItems([
  'abc123def456...',
  'def789ghi012...',
]);
```

See [Extensions & Events](/sdk/typescript/extensions#batch-requests) for more on `client.batch()`.

## ETag / Conditional Requests

ETag support is **enabled by default**. The SDK sends a cached fingerprint with each request — if the data hasn't changed, the server returns `304 Not Modified` (no body), saving bandwidth.

```ts
// First request: full response with ETag
const response = await cart.get();

// Second request: sends If-None-Match automatically
const response2 = await cart.get();
if (response2.isNotModified()) {
  console.log('Cart has not changed');
}
```

### Disable ETag

```ts
// Via constructor
const client = new CoCart('https://your-store.com', { etag: false });

// At runtime
client.setETag(false);
```

### Clear ETag Cache

```ts
// Force fresh responses on next request
client.clearETagCache();
```

### Skip Cache for a Single Request

```ts
const response = await cart.get({ _skip_cache: 'true' });
```

### Cache Status

```ts
const response = await cart.get();
console.log(response.getCacheStatus()); // 'HIT', 'MISS', or 'SKIP'
```

## Working with Responses

```ts
const response = await cart.get();

// Cart items
const items = response.getItems();

// Cart totals
const totals = response.getTotals();

// Item count
const count = response.getItemCount();

// Cart key (from headers)
const cartKey = response.getCartKey();

// Cart hash
const hash = response.getCartHash();

// Notices
const notices = response.getNotices();

// Tax lines, normalized to a flat array regardless of the store's tax display setting
const taxes = response.getTaxes();
if (response.hasTaxes()) {
  console.log(taxes[0].name, taxes[0].price);
}

// Dot-notation access
const subtotal = response.get('totals.subtotal');
const firstItemName = response.get('items.0.name');

// Check if key exists
if (response.has('totals.discount_total')) {
  console.log('Discount applied!');
}

// Full data
const data = response.toObject();
const json = response.toJson();
```

See [Error Handling](/sdk/typescript/error-handling) for handling API errors.
