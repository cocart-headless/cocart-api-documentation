## Overview

This endpoint completes the checkout process by creating an order and processing payment. Use this after collecting all necessary checkout information and customer details.

<Info>
    Unlike `POST /order-received/{order_id}/pay`, a payment failure here does **not** raise an HTTP error - the order is still created and a `200` is returned with `payment_result.payment_status` set to `failed`.

    When the gateway requires further customer action before payment can complete (e.g. 3D Secure/SCA), `payment_status` is `requires_action` and `action_type`/`action_data` describe what the client must do next (gateway-specific). The draft order and cart session are left intact - once the client completes the action, call `POST /checkout` again with the same cart/session to land on the same order rather than creating a duplicate.
</Info>
