## Requirements

| Dependency | Minimum version |
|---|---|
| WordPress | 6.3 |
| WooCommerce | 10.0 |
| PHP | 8.2 |
| CoCart | See the version table above for the plugin this reference applies to |

## Base URL

All requests are made to your WordPress site URL:

```
https://your-store.com/wp-json/cocart/
```

The v2 API namespace is `cocart/v2`. For example:

```
https://your-store.com/wp-json/cocart/v2/cart
```

## Authentication

CoCart supports three authentication methods:

| Method | Best for |
|---|---|
| **JWT** | Customer-facing apps (recommended) |
| **Basic Auth** | Server-to-server requests over HTTPS |
| **Consumer Keys** | Admin operations (Sessions API) |

For customer-facing storefronts, use JWT authentication — it issues short-lived access tokens with automatic refresh, and does not require WooCommerce admin API keys. See the [Authentication guide](/authentication) for setup and examples.

## Request/Response Format

The default response format is JSON. Requests with a message body use plain JSON to set or update resource attributes. Successful requests return a `200 OK` HTTP status.

Response notes:

- Resource IDs are returned as integers.
- Other numeric values, such as prices and item counts, are returned as integers or strings.
- Blank fields may return as `null` rather than an empty string or be omitted.

## Body Types

When making a request, use the correct `Content-Type` for the body format:

| Body type | Content-Type |
|---|---|
| form-data | `application/json` |
| raw | `application/json` |
| x-www-form-urlencoded | `application/x-www-form-urlencoded` |

<Note>
  Use **raw** when passing an object for `variation` or `cart_item_data`. Use [any of the available tools](/tools) to test requests if you're unsure.
</Note>

## Errors

| Error Code | Meaning |
|---|---|
| `400 Bad Request` | Invalid request, e.g. using an unsupported HTTP method. |
| `401 Unauthorized` | Authentication or permission error, e.g. incorrect credentials. |
| `403 Forbidden` | Not permitted to perform this action. |
| `404 Not Found` | Resource does not exist or is missing. |
| `405 Method Not Allowed` | Request method not supported for this resource. |
| `406 Not Acceptable` | Server could not produce a response matching the request. |
| `500 Internal Server Error` | Server-side error. |

Errors return both an HTTP status code and a JSON body with `code`, `message`, and `data` attributes.

**WordPress REST API error**

```json
{
    "code": "rest_no_route",
    "message": "No route was found matching the URL and request method",
    "data": {
        "status": 404
    }
}
```

**CoCart error**

```json
{
    "code": "cocart_clear_cart_failed",
    "message": "Clearing the cart failed!",
    "data": {
        "status": 406
    }
}
```

See the [error codes reference](/api-reference/v2/error-codes) for the full list of CoCart-specific error codes.
