                <p className="pillar-body">

                </p>
            </div>

            <div>
                <div className="pillar-label">Session Management</div>

                <h3 className="pillar-title">CoCart</h3>
                <p className="pillar-body">
                    Database-backed cart keys passed via <code>X-Cart-Key</code> header. No cookies, no GDPR consent banners, works across any client.
                </p>

                <h3 className="pillar-title">WooGraphQL</h3>
                <p className="pillar-body">
                    JWT tokens or WooCommerce Cart-Tokens for session persistence. Supports multiple state changes per request via a Session Transaction Manager, but you manage token storage and renewal yourself.
                </p>
            </div>

            <div>
                <div className="pillar-label">Caching</div>

                <h3 className="pillar-title">CoCart</h3>
                <p className="pillar-body">
                    Built-in ETag support with HTTP 304 responses. Cart and product endpoints return ETags automatically. SDKs handle <code>If-None-Match</code> headers for you.
                </p>

                <h3 className="pillar-title">WooGraphQL</h3>
                <p className="pillar-body">
                    No server-side caching. Relies on GraphQL client-side caching (Apollo normalized cache, urql document cache) which varies by client library.
                </p>
            </div>

    <div style={{maxWidth: '48rem', marginLeft: 'auto', marginRight: 'auto'}}>
        <AccordionGroup>
            <Accordion title="Can I use CoCart and WooGraphQL together?">
                Yes. They're separate WordPress plugins that don't conflict. Some teams use CoCart for cart and checkout operations and WooGraphQL for complex product queries. That said, most projects are simpler with a single API.
            </Accordion>

            <Accordion title="Is REST or GraphQL better for headless WooCommerce?">
                It depends on your team. REST is simpler to debug, test, and integrate — any HTTP client works. GraphQL gives you precise field selection and fewer round trips for complex queries. CoCart's REST API covers the vast majority of headless commerce use cases without the added complexity of GraphQL.
            </Accordion>

            <Accordion title="Does WooGraphQL have an official SDK?">
                WooGraphQL works with any GraphQL client (Apollo, urql) out of the box. Pro subscribers also get @woographql npm packages with React hooks and session utilities, plus a create-woonext-app CLI for Next.js scaffolding. CoCart provides official SDKs for TypeScript, PHP, Python, and Go with 12 framework adapters — available to all users at every tier.
            </Accordion>

            <Accordion title="How does pricing compare?">
                Both have a free tier. CoCart's paid plans are {"$59"} and {"$99"}/year. WooGraphQL Pro starts at {"$99.99"}/year (or {"$19.99"}/month) and goes up to {"$449.99"}/year for unlimited sites. The entry prices are similar, but CoCart includes official SDKs and framework adapters at every tier — WooGraphQL's npm packages and CLI require an annual Pro subscription.
            </Accordion>

            <Accordion title="Do I need to learn GraphQL to use WooGraphQL?">
                Yes. WooGraphQL requires understanding GraphQL queries, mutations, fragments, and how to work with a GraphQL client. CoCart uses standard REST endpoints that work with any HTTP client — no specialized knowledge needed.
            </Accordion>

            <Accordion title="How does CORS differ between the two?">
                CoCart has built-in CORS handling with configurable origin control via the `cocart_allow_origin` filter — no extra plugins needed. WooGraphQL requires installing the separate WPGraphQL-CORS plugin for cross-origin support. For headless stores where your frontend and backend are on different domains, CoCart's approach is simpler to set up and maintain.
            </Accordion>

            <Accordion title="Which one handles WooCommerce extensions better?">
                Both use WooCommerce's hooks system for extension compatibility, so most extensions work with either solution. CoCart has a [tested extensions list](/integrations) you can check for specific plugins.
            </Accordion>
        </AccordionGroup>
