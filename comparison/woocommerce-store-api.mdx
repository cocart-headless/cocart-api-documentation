    <div style={{maxWidth: '48rem', marginLeft: 'auto', marginRight: 'auto'}}>
        <AccordionGroup>
            <Accordion title="Can I use CoCart alongside the Store API?">
                Yes. CoCart is a separate plugin that registers its own REST endpoints. The Store API continues to work for WooCommerce Blocks while CoCart powers your headless frontend. There are no conflicts.
            </Accordion>

            <Accordion title="If the Store API is free, why pay for CoCart?">
                The Store API was designed to power WooCommerce Blocks, not headless frontends. CoCart gives you customer authentication, stable ETag caching across all endpoints, configurable CORS origin control, official SDKs with framework adapters, and dedicated support — things you'd otherwise have to build and maintain yourself.
            </Accordion>

            <Accordion title="Does the Store API support customer login?">
                No. The Store API is deliberately unauthenticated. It provides a Cart-Token for session continuity, but there's no way to log in a customer, access their order history, or maintain a persistent account. CoCart supports Basic Auth and JWT with email, username, or phone number login.
            </Accordion>

            <Accordion title="What's the difference between Cart-Token and CoCart's cart key?">
                Both are header-based session identifiers. The Store API's Cart-Token is returned when you first request the cart and you manage it yourself. CoCart's cart key is database-backed, and the SDKs handle storage (with encryption), session restoration, and automatic header injection through framework adapters.
            </Accordion>

            <Accordion title="Does the Store API have caching?">
                As of WooCommerce 10.5, there's an experimental ETag caching feature for product endpoints. It's opt-in, may have breaking changes, and requires a persistent object cache (Redis/Memcached) for full performance. CoCart's ETag caching is stable, built-in across all endpoints, and works without additional infrastructure.
            </Accordion>

            <Accordion title="How does CORS differ between the two?">
                Both handle CORS headers and preflight requests. The Store API's Cart-Token header allows cross-origin requests to proceed without cookie credentials, but origin control is left to your server or WordPress configuration. CoCart gives you explicit control through the `cocart_allow_origin` filter, letting you whitelist specific domains — no manual server configuration required.
            </Accordion>

            <Accordion title="Can I migrate from the Store API to CoCart?">
                Yes. Both are REST APIs with similar endpoint patterns. The main changes are the session mechanism (Cart-Token to X-Cart-Key), authentication headers, and the base URL namespace. If you use CoCart's SDK, much of this is handled for you automatically.
            </Accordion>
